# Consumer observations

The mutable eligibility of a Notion record is independent of the session's immutable content selection and proof of delivery. These finite models retain the original AH-864 audit cases and candidate state-transition rules. They do not model HTTP consistency or authorize production writes.

## Reproduce

Use the statechart commit and every runtime hash in `tool-lock.json`, with the declared TLC 1.7.4 jar. Keep tool binaries outside the repository. `PSTACK_STATECHART_ROOT` names the directory containing `scripts/run.ts`; `TLA2TOOLS` names the verified jar.

```sh
node scripts/verify-consumer-observations.mjs --out /new/absolute/model-output
bun test packages/context-broker/scripts/consumer-observation.test.ts packages/context-broker/scripts/host-prepare.test.ts --timeout 30000
node scripts/check-consumer-observation-mutations.mjs --out /new/absolute/mutation-output
```

The first command requires both environment variables. All output directories must be new. The runner retains complete reports, raw TLC output and original Mermaid generated by statechart; it verifies that every rule has a terminal outcome and exploration is complete. A missing tool, parse failure, timeout or truncated state space is not a property result. Owned temporary directories are retained rather than permanently deleted.

## Domain correspondence

| Model/property | Product owner | Real replay |
| --- | --- | --- |
| Availability / KnownObservationAgrees | `consumer-observation.ts` interprets current proof; `host-skills.ts` routes read, use and metadata through it | F1, F2, F3 and F4 in `host-prepare.test.ts` |
| Availability / CursorCannotMixAvailability | `notion_list` fingerprints actual effective availability, View, scope, query and coverage | F5; removing the effective-state hash fails the mutation replay |
| ReadRace / NewestObservationWins | observation generation, per-operation order and original validation evidence; graph commits recheck eligibility | F7 plus the older-success-after-new-denial case |
| ReadRace / NoCrossSessionPublication | existing lifecycle cancellation/generation and coordinator ticket admission | cancelled/read replacement cases; generation-negative model |

The `current` configurations deliberately retain the audit defects. Their expected failures are regression documentation, not the implementation's current status. `candidate` must satisfy every declared property. The cursor-negative and generation-negative controls must fail exactly their declared rules. The mutation script additionally removes two *actual code guards* in isolated copies: baseline succeeds, guard removal fails an assertion, and restored bytes succeed. It never changes the active checkout or live installation.

## Limits

Availability is bounded to one record and one saved cursor. ReadRace is bounded to two reads and two session epochs. Original validation time, cache origin, known permission denial, Requires attribution, full graph version vectors, provider body proofs and actual source polling have additional TypeScript/SDK/host tests; they are not proved by these finite models. In particular, the models do not prove server linearizability, a wall-clock order across machines, or all future races.

F6 uses the actual metadata consumer and a controlled clock at TTL-1, TTL and subsequent accesses, with concurrent readers and zero body loads. The existing actual installed HTTP suite and live Notion/Pi runs supply the separate transport evidence. Keep per-case source, package, model, native session and wire hashes outside the repository; synchronize `coverage.json` only after tracing the changed implementation and rerunning its affected tests.
