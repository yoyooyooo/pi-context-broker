## 修复内容

**完整原生读取没有记入已加载状态。** 模型自主read成功后，再使用`/skill:`会重复注入正文。现在把稳定身份、认证scope、快照、tool-call ID和字节哈希绑定到原始成功toolResult，后续`$`和原生入口共用加载判断。部分读取、失败、用户粘贴的XML、另一个认证scope或已压缩移除的正文不能伪装成已加载。

**会话恢复与资源路径。** 续接时显式恢复已选snapshot，不能以今天的current替代；Pi原生提示中的资源位置改为不可变导出目录，不再使用上个进程的临时metadata别名。实际会话切换清理内存归属，避免不同会话串状态。

**模型主动重读同一入口。** 原始工具结果继续完整保留，发送给模型的有效上下文只合并经过身份、snapshot和字节校验的重复指令，保留工具调用配对。不同版本或范围不合并；原副本被压缩后，剩余完整读回仍可成为唯一正文。

## 验收自身也做了修正

旧标准model helper在父控先读目标并使用同一CLI根，实际上预热了被测缓存；现已隔离oracle与消费者。View的POST查询不再误计为authoring。模型自己复述或思考中的标记不计作第二份导入正文，真实用户/工具消息中的重复仍会失败。

A/B期间更换追踪包装器路径曾诱发模型读取测试日志，观察器阻止后该轮保留失败；现保持完全相同的source argv。一次重跑又发现旧case目录把声称的空CLI变成暖缓存，现在按独立evidence目录分配新的case根。所有初次失败和中间复测结果保留，不覆盖成成功。
